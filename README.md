
## Запуск приложения (Docker)
Для их запуска убедитесь, что у вас запущен Docker (или Docker Desktop)

Для запуска приложения вместе с базой данных выполните команду в корне проекта:

```bash
docker-compose up -d --build
```
*Приложение будет доступно по адресу: http://localhost:8080*

Остановка с сохранением данных в контейнерах:
```bash
docker-compose stop
```

Остановка и удаление контейнеров (данные в томе `db_data` сохранятся):
```bash
docker-compose down
```

# Bank Transfer API

REST-сервис для надежного внутреннего перевода денежных средств между счетами и формирования банковской выписки.
Реализован с учетом строгих требований к транзакционности (ACID), безопасной работе в многопоточной среде (решение проблемы Deadlock) и принципов чистой архитектуры.

## Описание проекта
Данный микросервис симулирует работу ядра банковской системы (Core Banking). Он позволяет безопасно переводить средства с одного счета на другой, гарантируя, что деньги не будут потеряны или "размножены" при одновременных запросах.

Также сервис предоставляет возможность генерации выписки по счету за выбранный период с пагинацией и **динамическим расчетом накопительного итога (rolling balance)** для каждой операции, используя продвинутые возможности SQL (Window Functions).

## Используемые технологии
- **Java 21**, **Spring Boot 3** (Web, Data JPA, Validation)
- **PostgreSQL 16** (Реляционное хранилище)
- **Hibernate / JDBC Template** (Доступ к данным)
- **Testcontainers, JUnit 5, MockMvc** (Интеграционное тестирование)
- **Docker & Docker Compose** (Контейнеризация)
- **Lombok**, **SLF4J** (Логирование)

## Архитектурные решения и Паттерны

1. **Double-entry bookkeeping (Двойная запись)**:
   Финансовые операции реализованы через бухгалтерский принцип двойной записи. Одна транзакция (`Transaction`) порождает две записи в таблице `entries` (Дебет для счета-отправителя и Кредит для счета-получателя), что исключает расхождение балансов и упрощает аудит.
2. **Защита от состояния гонки (Race Condition)**:
   Использована пессимистичная блокировка `@Lock(LockModeType.PESSIMISTIC_WRITE)` на уровне строк БД при обращении к счетам (`SELECT ... FOR UPDATE`).
3. **Предотвращение Deadlock (Взаимоблокировок)**:
   При переводе счета сортируются перед захватом блокировки в базе данных (`request.from().compareTo(request.to())`). Это гарантирует, что конкурентные переводы (например, A -> B и B -> A) будут пытаться захватить ресурсы в одинаковом порядке.
4. **Паттерн Validation Pipeline / Chain of Responsibility**:
   Логика предтранзакционных проверок вынесена в интерфейс `PreTransferProcessing`. Проверки (статус счетов `AccountStatusProcessor`, наличие средств `SufficientFundsProcessor`) применяются цепочкой. Это позволяет легко добавлять новые бизнес-правила (например, лимиты, антифрод) без изменения основного `TransferExecutor`.
5. **Оконные функции (Window Functions) для выписки**:
   Расчет выписки (`balanceAfter`) реализован на уровне PostgreSQL с использованием нативного SQL-запроса с CTE (`WITH t_start ...`) и оконных функций (`SUM(amount) OVER(ORDER BY ...)`). Это позволяет вычислять накопительный баланс налету прямо в базе данных, поддерживает пагинацию и избавляет от необходимости загружать тысячи записей в память JVM.
6. **Централизованная обработка ошибок**:
   Использована иерархия бизнес-исключений (наследуются от `TransferException`) и `GlobalExceptionHandler` (`@RestControllerAdvice`). Клиенту возвращаются четкие и структурированные JSON-ответы с описанием ошибки.
7. **Value Objects & Records**:
   Использование Java Records (`TransferRequest`) для DTO и оберток (`AccountNumber`) для повышения читаемости и безопасности типов (Domain-Driven Design).

## API Endpoints

### 1. Перевод средств
`POST /api/transfers`

**Request Body:**
```json
{
  "from": "111222333",
  "to": "444555666",
  "amount": 1500.50,
  "description": "Оплата услуг"
}
```
**Response:** `200 OK` (В случае успеха) или `400 Bad Request` / `404 Not Found` с детальным описанием бизнес-ошибки.

### 2. Получение выписки по счету
`GET /api/accounts/{accountNumber}/statement?from=2026-03-01&to=2026-03-31&page=0&size=10`

Возвращает список операций за указанный период с расчетом остатка на счете (`balanceAfter`) после каждой операции.

**Response:** `200 OK`
```json
{
  "content":[
    {
      "date": "2026-03-05T10:00:00Z",
      "type": "DEPOSIT",
      "amount": 500.00,
      "balanceAfter": 1300.00
    },
    {
      "date": "2026-03-06T15:00:00Z",
      "type": "WITHDRAWAL",
      "amount": -100.00,
      "balanceAfter": 1200.00
    }
  ],
  "pageable": {
    "pageNumber": 0,
    "pageSize": 10
  },
  "totalElements": 2
}
```
